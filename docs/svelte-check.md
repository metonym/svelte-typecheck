# Compared with svelte-check

|                | svelte-check                    | svelte-typecheck                                                  |
| :------------- | :------------------------------ | :---------------------------------------------------------------- |
| Type checker   | TypeScript's JS API (TS 5 or 6) | Any checker that reads a tsconfig: `bun check`, tsrs, tsgo, `tsc` |
| TypeScript 7   | Needs `typescript@~6` beside it | Works: never imports `typescript`                                 |
| Dependencies   | 6, plus `typescript` (24 MB)    | None: [sveast](https://github.com/metonym/sveast) is bundled      |
| Svelte 3, 4, 5 | Yes                             | Yes, runes included                                               |

## Beyond svelte-check

What svelte-typecheck does that svelte-check doesn't:

|                                   |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :-------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Any checker, TypeScript 7**     | Checks with your project's `tsc`, including TypeScript 7's native one, or tsgo, tsrs or `bun check`; svelte-check needs TypeScript 5 or 6's JS API. See [Bring your own checker](checkers.md).                                                                                                                                                                                                                                                                                                                                                                             |
| **Baselines**                     | `--update-baseline --baseline errors.json` records today's diagnostics; `--baseline errors.json` then reports, and fails on, only new ones. A diagnostic is known by its file, code, message and line's text, not its line number, so edits around it don't make it new; fixed ones are counted, to drop with `--update-baseline`, and `--strict-baseline` fails until they are, so it only goes down. For turning on `strict`, a new rule, or a checker upgrade without fixing everything first. Its paths are the workspace's, so the file is the same on every machine. |
| **Output for coding agents**      | Under Claude Code or Codex, or with `AGENT` or `AI_AGENT` set, each problem prints with its code and the source lines around it, then one summary line, in the layout `bun check` and `bun lint` use for agents. An agent can read the error and its code without opening the file. svelte-check prints its `machine` format under Claude Code, with no code or source. `--output agent` picks it anywhere, and `--output machine` turns it off. See [`--output`](cli.md).                                                                                                 |
| **Changed files only**            | `--changed` and `--since <ref>` report the files git sees changed and the files that import them, whose errors a change can cause. The whole program is still checked, so the errors are the same ones, fewer to read: for a pre-commit hook, or a PR's CI run.                                                                                                                                                                                                                                                                                                            |
| **Speed and memory**              | Up to 11× faster than svelte-check with `bun check` or tsrs, at about half its memory, and 1.2 to 2× with TypeScript 6's own `tsc`: one checker process over files on disk, beside the compiler pass, where svelte-check drives TypeScript's language service file by file.                                                                                                                                                                                                                                                                                                |
| **Zero dependencies**             | One bundle: it uses the project's own Svelte and checker, and installs nothing else.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Generated code you can read**   | The TypeScript it writes and its tsconfig are plain files in `--out-dir`: open them, or run any checker on them yourself. They're kept between runs, with the checker's own build cache, so a run after a change rewrites and rechecks only what it touches (`--no-incremental` starts over). [How it works](architecture.md#the-generated-code) shows what it writes for a component, next to svelte2tsx's output.                                                                                                                                                        |
| **Generic JS legacy components**  | A JS component with `generics="…"` and `export let` props is generic to its users, as the same component in TS is. svelte-check types its props as `boolean`, so it reports an error at each use, even a valid one.                                                                                                                                                                                                                                                                                                                                                        |
| **No silent passes**              | Generated code that doesn't parse fails the run as a svelte-typecheck bug, and a checker error that names no file (a tsconfig option, a root file) is reported on the tsconfig. svelte-check's language service reads past broken generated code.                                                                                                                                                                                                                                                                                                                          |
| **Warnings in Svelte modules**    | Compiler warnings in `.svelte.js` and `.svelte.ts` modules, such as `state_referenced_locally`, as a build gives them; svelte-check compiles only components ([language-tools#2891](https://github.com/sveltejs/language-tools/issues/2891)). `// svelte-ignore` and `--compiler-warnings` apply. A `.svelte.ts` module's types are blanked in place before it compiles, so a module with an `enum` or a parameter property, which have a runtime meaning, isn't compiled.                                                                                                 |
| **GitHub annotations**            | `--output github` prints each problem as a workflow command, so a PR shows it on its diff, at its line. svelte-check needs a problem matcher you write yourself ([language-tools#1036](https://github.com/sveltejs/language-tools/issues/1036)).                                                                                                                                                                                                                                                                                                                           |
| **`--tsgo` bugs it doesn't have** | Checked against svelte-check 4.7.8 with TypeScript 7. A component that doesn't parse fails the run, where `svelte-check --tsgo` exits 0 ([language-tools#3185](https://github.com/sveltejs/language-tools/issues/3185)). A deleted component's errors go with it ([#3157](https://github.com/sveltejs/language-tools/issues/3157)). Output piped under Bun arrives whole past 64 KB ([#3179](https://github.com/sveltejs/language-tools/issues/3179)).                                                                                                                     |

## Differences from svelte-check

- **CSS diagnostics** (`--diagnostic-sources css`): accepted, but nothing is reported. svelte-check runs a CSS language service on `<style>`, a dependency this package leaves out; Svelte's compiler still reports invalid CSS.
- **The default output under a coding agent** is `agent`. svelte-check prints `machine` when `CLAUDECODE=1`. Pass `--output machine` for svelte-check's output.
- **`COMPLETED <n> FILES`** counts components, not every file in TypeScript's program.
- **`--diagnostic-sources svelte`** with a tsconfig reports no type errors, as svelte-check's docs say; svelte-check itself reports them.
- **`--tsgo-experimental-api`** is accepted, and does what `--tsgo` does.
- **tsconfig option errors** that only matter to an emitting build, such as a JS file that `tsc` would overwrite, aren't reported: the checker runs with `noEmit`.
- **A union's members** can print in another order, as TypeScript orders them by when it first meets each type: `Element | Document` where svelte-check has `Document | Element`.
  The same order picks what a generic call infers from a union: `render(cond ? A : B, …)` with two components can be an error in one tool and not the other, as each checks its files, and so meets the types, in its own order.
- **A syntax error in a TS or JS file** stops `tsc` and the other CLI checkers from type-checking at all, so only syntax errors are reported until it's fixed; svelte-check's language service reports the type errors in other files too. A component's syntax errors don't do this.
- **Svelte 3 and 4 with `lang="ts"` and no preprocessors**: svelte-check strips the types with a fallback preprocessor and reports the compiler's warnings; here the compiler can't read the script, so there are none.
- **`generics` that don't parse**, such as a conditional type as a constraint: svelte-check pastes the text in more places, so it reports more syntax errors, and type errors they cause. Here only the first ones are reported, at the same positions.
- **A JS component with a `@template` tag and no `generics`**: svelte-check reports an error at each use, even a valid one, as it keeps `T` unresolved. Here the component isn't generic: each prop is typed by its constraint.
- **Svelte 5 with TS-only syntax and no preprocessors**, such as an `enum` or a constructor's `private` parameter: svelte-check strips the types first, so the compiler never sees them. Here the compiler reports that it doesn't support them, and stops, so the file's other compiler warnings are lost.
- **Svelte 3's element types** are Svelte 4's, read from the project's `svelte/elements`, without svelte2tsx's deprecated `svelte.JSX` namespace: a project that augments or references `svelte.JSX` should move to `svelteHTML` or `svelte/elements`. An ARIA attribute's type prints as `Booleanish` where svelte-check spells out `boolean | "true" | "false"`.
- **Slot content for a Svelte 5 component without a `children` prop** is reported at the tag's name. svelte-check places the error where svelte2tsx's text rewriting happens to anchor its inserted `children`: an attribute's opening quote, the start of a line, or after an attribute.
- **`--out-dir` outside the project** can't find its packages from the generated code; the default is inside `node_modules`.
- **`<svelte:element this={tag}>` whose tag may be any element**, such as a component's generic `Tag extends keyof HTMLElementTagNameMap`: svelte-check reports TypeScript's "union type too complex" and checks none of the element's attributes; here its attributes are checked as an element's. An attribute error on it names the attributes' type with the tag widened: `keyof HTMLElementTagNameMap extends Tag ? string : Tag`.
- **A repeated `on:` on `<svelte:document>`**, such as two `on:click`s: svelte-check reports TypeScript's "An object literal cannot have multiple properties with the same name" about its generated code, as it drops that error on other elements only. Here it isn't reported on any element.

## Limitations

- **Type-checking only:** no editor support. Your editor keeps the Svelte language server, which can disagree with it at the edges.
- **No CSS diagnostics.**
